The "Java vs. Silk" naming story is also basically right, though the more precise history (from a 1996 JavaWorld interview reprinted by InfoWorld) credits product manager Kim Polese with proposing both names and making the final call, with Gosling favoring Java over Silk — the slide's framing ("According to James Gosling...") isn't wrong, just slightly simplified.

Factual correction — worth knowing, not just trivia · Week 4

The slide states "Java is an island of Indonesia where first coffee was produced." This part is inaccurate: coffee did not originate in Java — it originated in Ethiopia and was first cultivated commercially in Yemen. Java became one of the world's largest coffee exporters only after Dutch colonists smuggled coffee plants there in 1696, which is why "java" became a nickname for coffee in general. The slide's wording is a very commonly copy-pasted line across student tutorials (it appears near-verbatim on several other sites), so this isn't a one-off error — but it is worth quietly correcting in your own notes.

No current browser has run Java applets since the mid-2010s. The slide isn't factually wrong for the JDK version it was written against — but if this comes up in a lab or exam today, know that "Application" is effectively the only one of the two you'll ever actually run. See the deprecation callout in Chapter 03.

Added context, not a correction · Week 2

The slide's 4-step Programming Cycle (Problem definition → Problem analysis → Algorithm development → Coding and debugging) is a standard, accepted simplification. Some textbooks split it into 5–6 steps by separating "testing" and "documentation" out from "coding and debugging." Both versions are taught; the slide's 4-step version is what's testable for this course.

CHAPTER 01 · WEEK 2
Program Logic Formulation

This week establishes the vocabulary you'll use for the rest of the course: what a program actually is, the four-stage cycle every program goes through before it runs, and the two tools (algorithms and pseudocode) used to plan a program's logic before writing a single line of Java.

What Is a Computer Program?

A computer program (also called a software program, or just a program) is a sequence of instructions written to perform a specified task for a computer. The slide illustrates this with familiar software: Java, Microsoft Windows, C++, Microsoft Visual Basic, and Microsoft Access.

The Programming Cycle

Before code gets written, a program passes through four stages:

1
Problem Definition
Nailing down exactly what the program needs to accomplish — what inputs it receives and what output it must produce.
2
Problem Analysis
Breaking the problem down into its component parts and identifying what data and operations are actually needed.
3
Algorithm Development
Designing the step-by-step logic that solves the problem — typically expressed as pseudocode or a flowchart.
4
Coding and Debugging
Translating the algorithm into an actual programming language (Java, in this course), then finding and fixing errors.
🔗
Forward Link

Stage 3 (Algorithm Development) is exactly what the rest of this chapter and all of Week 3 build toward — every flowchart and pseudocode example you learn is a way of doing this stage well before you ever touch Java syntax.

Algorithm

An algorithm is a step-by-step problem-solving procedure, especially an established, recursive computational procedure for solving a problem in a finite number of steps.

Characteristics of a Valid Algorithm

  • Specify each step or instruction exactly — no ambiguity about what to do next.
  • There must be a finite number of steps — it has to actually end.
  • There must be an output — it has to produce a result.

Pseudocode

Pseudocode is a generic way of describing an algorithm without using any specific programming language's syntax. It cannot be executed on a real computer, but it models and resembles real programming code and is written at roughly the same level of detail. Pseudocode is an artificial, informal language that helps programmers develop algorithms — it reads very similarly to everyday English.

Pseudocode
If student's grade is greater than or equal to 60
    Print "passed"
else
    Print "failed"

Steps in Problem Solving

  • First produce a general algorithm (pseudocode works well for this).
  • Refine the algorithm successively to get a step-by-step detailed algorithm that is very close to a computer language.
Tag: ADDED
Glossary Word Check
"Recursive" in the algorithm definition doesn't mean the same thing as a recursive function you'll meet later — here it just means the procedure follows a fixed, repeatable set of rules, the general dictionary sense of the word.
Tag: ADDED
Recitation-Ready Line
If asked "what's the difference between an algorithm and pseudocode?" — an algorithm is the logic; pseudocode is one common way of writing that logic down in a language-neutral, English-like form.

Scenario-Based Problems

Problem 1
Q: You're handed a one-paragraph description of what a payroll program needs to do, and you write down exactly what inputs it takes (hours worked, rate) and what output it must produce (gross pay). Which stage of the Programming Cycle is this?
Solution: This is Problem Definition — you're establishing scope (inputs/outputs), not yet breaking the problem into parts (Analysis) or designing the logic (Algorithm Development).
Problem 2
Q: Write pseudocode for a program that asks the user for a number and prints "Even" or "Odd."
Solution, step by step:
Pseudocode
Get num
If num MOD 2 is equal to 0
    Print "Even"
else
    Print "Odd"
The remainder (MOD) of an even number divided by 2 is always 0, so that's the condition to test.
Problem 3
Q: A classmate submits this as an "algorithm": "Keep guessing numbers until you win the lottery." Which characteristic of a valid algorithm does this violate?
Solution: It violates "there must be a finite number of steps." There's no guarantee the process ever ends — it could run forever without ever producing a result, which also means it fails the "must produce an output" test in practice.

CHAPTER 02 · WEEK 3
Logic Formulation Cont. — Flowcharts, Decisions & Loops

This is the densest week in the set: flowchart symbols, the two families of boolean operators, and the three building blocks (selection, repetition, and their combinations) that every program's control flow is made of. Everything here maps directly onto Java's if/else and loop statements in Chapter 03 and beyond.

What Is a Flowchart?

A flowchart is a chart that contains symbols referring to computer operations, describing how the program performs. Symbols such as squares, diamonds, and ovals represent various operations; these symbols are connected by lines and arrows to indicate the flow of data or control from one point to another.

Multiple Decision Boxes

Scenario: Ask the user for a number 1–3. If 1, print "Hello"; if 2, print "Hi"; if 3, print "Bye"; otherwise print "Invalid."

Java
// x has already been read from the user
if (x == 1) {
    System.out.println("Hello");
} else if (x == 2) {
    System.out.println("Hi");
} else if (x == 3) {
    System.out.println("Bye");
} else {
    System.out.println("Invalid");
}

Decision Boxes with Ranges

Scenario: Print the supervisor's name for a given department number — 1–3 → Mr. X, 4–7 → Mr. Y, 8–9 → Mr. Z. The slide's flowchart tests the lowest boundary of each range first.

Java
// dept has already been read from the user
if (dept <= 3) {
    System.out.println("Mr. X");
} else if (dept <= 7) {
    System.out.println("Mr. Y");
} else {
    System.out.println("Mr. Z");
}
🔎
Trace it: dept = 5

dept <= 3 → 5 <= 3 is FALSE → check next → dept <= 7 → 5 <= 7 is TRUE → prints "Mr. Y".

Looping Constructs

A repetition structure (loop/iteration) repeats one or more instructions until a certain condition is met. The action performed inside the loop must eventually cause it to terminate — otherwise it becomes an infinite loop.

🛑
The Infinite Loop Trap

The slide's example tests X < Y? and displays X — but never changes X. Since X never changes, the condition never becomes FALSE, and the loop runs forever. The fix: add an action inside the loop that changes X, e.g. X = X + 1. This is called a pre-test repetition structure — the condition is tested before any action runs, so if the condition is false to begin with, the loop body never executes at all.

Java — corrected loop
int x = 0, y = 10;
while (x < y) {
    System.out.println(x);
    x = x + 1;   // without this line, the loop never ends
}

Worked Example: Gender Validation, Repeated 5 Times

Scenario: Ask the user for a gender. If 'M', display "MALE"; if 'F', display "FEMALE"; otherwise display "Invalid Gender" and let the user re-enter. Repeat the whole process 5 times.

Java
String gen = "";
int ctr = 1;
while (ctr <= 5) {
    // gen has been read from the user here
    if (!gen.equals("M") && !gen.equals("F")) {
        System.out.println("Invalid");
    } else if (gen.equals("M")) {
        System.out.println("Male");
    } else {
        System.out.println("Female");
    }
    ctr = ctr + 1;
}

ADDED Note how the flowchart's Gen != 'M' AND Gen != 'F' decision box becomes !gen.equals("M") && !gen.equals("F") in Java — the AND from the truth table above is written &&, and string comparison uses .equals() rather than == (a rule you'll meet formally once Java strings are covered in more depth).

Multiple Loops

It's possible to have a loop within a loop. When loops are nested, it's critical to determine exactly what condition will terminate the whole flowchart — not just the inner loop.

Scenario-Based Problems

Problem 1
Q: Using the department/supervisor decision structure above, what prints for dept = 9?
Solution: 9 <= 3 → FALSE. 9 <= 7 → FALSE. Falls to else → prints "Mr. Z."
Problem 2
Q: This loop never stops. Find and fix the bug: int x = 0; while (x < 10) { System.out.println(x); }
Solution: The condition x < 10 is tested every pass, but nothing inside the loop changes x — it stays 0 forever, so the condition is always TRUE. Fix: add x = x + 1; as the last line inside the loop body.
Problem 3
Q: Design the logic (flowchart description + pseudocode) for: ask for a score, print "Pass" if 75 or above, otherwise "Fail," repeated 3 times.
Solution: Flowchart: Start → Ctr=1 → loop while Ctr<=3 → Get Score → Decision Score>=75? → Yes: Print "Pass" / No: Print "Fail" → Ctr=Ctr+1 → back to loop test → Stop.
Pseudocode
Ctr = 1
while Ctr <= 3
    Get Score
    if Score >= 75
        Print "Pass"
    else
        Print "Fail"
    Ctr = Ctr + 1

CHAPTER 03 · WEEK 4
Introduction to Java Programming

This week shifts from language-agnostic logic to Java specifically: where the language came from, what makes it distinct, how a Java program is structured, and the compile-then-interpret cycle that turns your source code into something that actually runs.

What Is Java?

Java was created in 1991 by James Gosling, Mike Sheridan, and Patrick Naughton of Sun Microsystems. It was first called "Greentalk" (file extension .gt), then renamed Oak as part of the Green Project, then finally renamed Java because "Oak" was already trademarked by another company (Oak Technology).

1991
Green Project begins
Gosling, Sheridan, and Naughton start work at Sun Microsystems; the language is first called Greentalk, then Oak.
1995
Renamed Java, publicly announced
Oak is renamed Java (a trademark conflict with Oak Technology forced the change); Time magazine names it one of the Ten Best Products of 1995.
1996
JDK 1.0 released
January 23, 1996 — Java's first public developer kit.

Why "Java"?

  • According to the naming story, "Java" and "Silk" were the top two choices under consideration.
  • Java was so unique that most of the team preferred it over the alternatives.
  • "Java" is named for the Indonesian island long associated with coffee — the developers were known coffee drinkers, which is also why the Java logo is a coffee cup. See Verification Notes: coffee did not originate in Java, but Java became a major coffee-exporting region.

Java Program Cycle

Use any text editor to create your source code (a .java file). The source code is compiled according to the JVM to produce byte code (a .class file). The byte code is then executed using an interpreter.

1
Source Code
Write HelloQCU.java in any text editor.
2
Compiler
Turns the source into byte code — HelloQCU.class.
3
JVM / Interpreter
Reads the byte code and executes it, producing the program's output.

No modern web browser has supported Java applets since roughly the mid-2010s, and the java.applet package no longer exists in current JDK releases at all. Treat "Applet" in this lesson as historical context for understanding why Java was originally designed the way it was — not as something you'll ever compile and run. Java Program Structure

  • A program is made up of one or more classes.
  • A class contains one or more methods.
  • A method contains program statements.
  • A Java application always contains a method called main.

Anatomy of a Java Program

    public static void main(String[] args) {
        System.out.println("Hello QCU!");
    }
}

Bonus terms an oral defense might ask next: "method" vs. "function" (Java calls them methods because they belong to a class), "argument" vs. "parameter" (args is the parameter; whatever you actually pass in when running the program is the argument), and "block" vs. "body" (the block is the { } pair; the body is what's inside it).

The main() Method — Rules

  • When executing a Java application, the JVM loads the class and invokes the main() method of that class.
  • main() must be declared public, static, and void.
  • A source file may have one or more classes.
  • Only one class — the one matching the file name — may be declared public.

Organizing a Java Application

  • Source code: filename.java
  • Class file: classname.class (matches the class name, produced by the compiler)
  • The compiler searches for a class file when it encounters a reference to a class in a .java file; the interpreter searches for .class files at runtime — both search the directories listed in the classpath variable.

Package Naming Tips

Java
package course;
public class Student {
    // code goes here
}

The qualified name for this class is course.Student, stored at the path course/Student.java. To use it elsewhere: import course.Student; (a single class) or import course.*; (every class in the package). Packages make classes easier to find, avoid naming conflicts between identically-named classes in different packages, and provide access control.

Scenario-Based Problems

Problem 1
Q: Find the error: class HelloQCU { public static void main(String[] args) { System.out.println("Hi") } }
Solution: Missing semicolon after System.out.println("Hi") — every statement in Java must end in ;. Corrected: System.out.println("Hi");
Problem 2
Q: You need a program that only ever runs on the student's own laptop, with no browser involved. Applet or Application — and why?
Solution: Application — an Applet is specifically designed to run inside a browser, and (per the deprecation callout above) the Applet API no longer exists in current Java releases at all, so it isn't a real option today either way.
Problem 3
Q: Your file is named Main.java, but the public class inside it is declared public class HelloWorld { ... }. Will this compile? Why or why not?
Solution: No — Java requires that only one class, matching the file name, may be declared public. Since the file is Main.java, the public class inside it must be named Main, not HelloWorld.
